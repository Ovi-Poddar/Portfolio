RAG-Gym #6

More reliable
answer evaluation

The evaluator could extract A from “Answer choice: D.” The submitted fix prioritizes explicit answer formats and narrows the fallback to a unique standalone label.

7 CPU tests passed · CLI regression coverage
Technical overview

Cause: an unconditional regex selected the first capital A/B/C/D anywhere in the response.

Change: recognize bare labels, retain structured patterns, and use a unique standalone-letter fallback.

Evidence: failing baseline tests, passing unit and CLI tests, and open-ended QA controls.

Agent Lightning #702

Reward validation
for agent training

A value valid as a Python float can become infinity in float32. The submitted change rejects non-finite rewards and out-of-range training values before conversion.

24 CPU regression cases · training-path checks
Technical overview

Cause: a finite value such as 1e40 exceeds float32's finite range.

Change: validate rewards and fallbacks, with errors identifying the rollout. Preserve large finite validation metrics.

Evidence: boundary cases and a local event-API-to-training-tensor reproduction.

LightRAG #4312

Recoverable
document deletion

Partially deleted documents could retain a healthy-looking status. The submitted change exposes deletion-in-progress state and keeps interrupted work visible for retry.

Deletion lifecycle tests · status & UI changes
Technical overview

Problem: interrupted cleanup can leave document status inconsistent with stored data.

Change: track DELETING state, isolate it from ingestion, preserve it during scans, and expose it in the interface.

Evidence: focused deletion lifecycle and frontend tests described in the PR.

Hugging Face PEFT #4133

Layer selection
in adapter merging

Weighted merging can inherit the first adapter's targeting filters and omit another adapter's layers. Reversing source order changes which layers survive.

18 CPU reproduction cases · LoRA & IA³
Technical overview

Cause: combined configurations retain the first source's exclusion filters; LoRA layer-index filters are affected too.

Evidence: LoRA and IA³ toy-model cases, save/reload checks, and a tiny random Llama reproduction.

Proposal: preserve the source-target union or explicitly reject incompatible filters, subject to maintainer guidance.

Amazon Product Price Prediction — LLM & ML Engineering

2026

LLM Engineering Capstone · 2026

Built an end-to-end text-to-price prediction pipeline from Amazon product metadata — data curation and LLM-assisted preprocessing through classical NLP/ML baselines, deep learning, frontier LLM benchmarking, and parameter-efficient fine-tuning. Evaluated 15+ approaches across the full modeling lifecycle. QLoRA-tuned Llama 3.2 3B achieved the best MAE ($39.85) among the evaluated approaches.

  • Curated and preprocessed noisy Amazon product metadata from the McAuley Amazon Reviews 2023 dataset into model-ready text representations.
  • Used the Groq API to transform raw listings into compact structured descriptions; prepared a 20K-sample curated dataset (up to 800K in later experiments).
  • Established NLP/ML baselines with Bag-of-Words / vectorization and Linear Regression, Random Forest, and XGBoost ($68.23 MAE).
  • Built a custom PyTorch network over vectorized features ($46.49 MAE) and benchmarked zero-shot frontier LLMs on the same task.
  • Fine-tuned GPT-4.1-nano via the OpenAI API and compared against zero-shot baselines, including cases where fine-tuning did not improve performance for the available training setup.
  • Fine-tuned Llama 3.2 3B with QLoRA/PEFT and 4-bit quantization; achieved the lowest MAE ($39.85) among evaluated classical ML, neural, and LLM-based approaches.
  • Developed a reusable evaluation framework with parallel inference, MAE benchmarking, Plotly visualization, and error analysis across 15+ model variants.
